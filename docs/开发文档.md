## 1. 项目概述

### 1.1 背景

安卓设备在开发、测试、交付、日常折腾场景中，常需要执行"把 APK 装到手机上""看看应用装没装、版本对不对""把手机里的文件拷出来""抓一下日志"等操作。命令行 `adb` 能力齐全，但存在三个门槛：

1. **命令与参数需要记忆**：`install -r -d -t -g`、`pm install-create` 等组合繁琐；
2. **无线调试的配对流程对普通用户不直观**：Android 11 引入的"无线调试"需要 IP、配对端口、连接端口、6 位配对码，且配对端口与连接端口不是同一个；
3. **失败信息不可读**：`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 之类的返回码没有解释，也没有下一步建议。

WireDeck 的目标是把上述流程收敛为一个**图形化、可批量、可回溯**的桌面工具。

### 1.2 产品定位

一句话：**把 `adb` 的无线连接与 APK 安装能力，做成一个开箱即用的桌面客户端。**

核心体验目标：

- 手机开启"无线调试"后，电脑端**自动发现**设备，输入 6 位配对码即可连上；
- 把 APK 文件**拖进窗口**就完成安装，支持批量、支持覆盖安装、支持多 split；
- 任何失败都给出**人类可读的原因 + 处理建议**，并保留原始日志；
- 全程不需要用户打开终端。

### 1.3 核心场景

| 编号 | 场景 | 说明 |
| --- | --- | --- |
| S0 | 有线快装 | 数据线直连，适合大批量装机，以及无线不可达时的兜底 |
| S1 | 日常装包 | 拖拽单个 APK → 选中设备 → 安装 → 看到成功与版本号 |
| S2 | 批量装机 | 一次拖入多个 APK 或一个目录，排队依次安装到同一设备 |
| S3 | 多设备分发 | 同一份 APK 依次安装到已连接的 N 台设备 |
| S4 | 版本排查 | 查看已安装应用列表、版本号、签名，对比本地 APK 与设备版本 |
| S5 | 现场支持 | 同一局域网内连上客户手机，抓日志、截图、导出应用 |
| S6 | 应用维护 | 卸载、停用、清数据、拉起、导出 APK |

### 1.4 非目标（本期明确不做）

- ❌ 不做应用商店 / APK 下载源，不内置任何第三方应用分发；
- ❌ 不做 Root 相关能力（不依赖 su、不刷机）；
- ❌ 不做 iOS 设备管理；
- ❌ 不做云端账号体系与远程公网穿透（局域网直连；如后续需要，另立项目）；
- ❌ 不做完整文件管理器的全部能力（本期只做推、拉、截图、录屏导出）。

### 2.2 关键约束

| 约束 | 影响 | 应对 |
| --- | --- | --- |
| Android 11+ 才有无需 USB 的"无线调试"配对 | 低版本设备无法纯无线首连 | 提供 USB 引导 `tcpip` 流程；文档明确版本要求 |
| 配对端口 ≠ 连接端口 | 用户极易混淆 | 向导分两步展示，端口分别校验 |
| 部分厂商限制 USB/无线安装 | 小米、OPPO、vivo 等默认关闭"USB 安装"，且与"USB 调试"是两个独立开关 | 错误码映射给出具体开关路径；设备卡片提供"USB 安装自检" |
| 首次 USB 连接需设备端 RSA 授权 | 未授权时设备状态为 `unauthorized`，所有操作失败 | 检测后提示"请在手机上点击允许调试"，并自动重试一次 |
| 同一台设备同时只能被一个 adb server 独占 | 与 Android Studio / 其他工具冲突 | 默认使用独立 server 端口（非 5037），或复用用户 server |
| 鸿蒙 HarmonyOS NEXT 不再支持 adb | 纯血鸿蒙无法连接 | 启动检测时识别并明确提示不支持 |
| macOS 需本地网络权限 | mDNS 发现失败 | `Info.plist` 声明 + 引导授权 |
| WKWebView 与 Chromium 存在渲染差异 | UI 表现可能与设计稿不一致 | 组件库选型保守；真机走查；避免 Chromium 专属 API |
| Google platform-tools 再分发条款 | 不能无脑打包进安装包 | 首次启动下载 + SHA-256 校验，或引导用户指定已有路径 |
| 面向外部用户分发（暂无付费开发者账号） | 未公证包首次打开被 Gatekeeper 拦截 | Ad-hoc 签名 + 通俗放行指引；后续可升级 Developer ID（见 11.2） |

## 3. 技术选型

### 3.1 决策记录（ADR-001）

**背景**：初版方案为 Electron，评估后认为安装体积（100–150MB）与常驻内存（250–400MB）对本项目偏重——本应用的 UI 只是表格、表单与日志流，真正的负载在 adb 子进程与网络传输，Chromium 运行时属于整包冗余。

**决策**（2026-10-30）：采用 **Wails v2**，Go 编写后端，系统 WebView 渲染前端。

**备选与结论**

| 方案 | 壳 | 体积（经验值） | 后端语言 | 本机就绪 | 结论 |
| --- | --- | --- | --- | --- | --- |
| Electron | 自带 Chromium | 100–150 MB | Node/TS | ✅ | 弃用（偏重） |
| **Wails v2** | 系统 WKWebView / WebView2 | 25–35 MB | Go | ✅ Go 1.27.3 已装 | **采用** |
| Tauri 2 | 系统 WebView | 20–30 MB | Rust | ❌ 需装 Rust | 备选（Rust 学习成本） |
| Node 服务 + 浏览器 | 无壳 | ~0 | Node/TS | ✅ | 备选（无独立窗口） |
| Neutralino.js | 系统 WebView | ~10 MB | C++ 扩展 | 需自补原生 | 不采用（后端能力弱） |

**理由**

1. 本机 Go 1.27.3、Xcode CLT 已就绪，**零安装成本**即可开工；
2. Go 的 `os/exec` + `context` 天然适合管理 adb 长驻子进程与超时取消；
3. mDNS 发现**不需要语言级库**——`adb mdns services` 已由 adb server 完成发现，后端只需解析文本，抹平了 Go/Rust 的生态差异；
4. 前端 Vue 3 + TS + Vite 完全复用，Wails 提供官方 `vue-ts` 模板；
5. 体积约为 Electron 的 1/4，内存约一半。

**代价与约束**

- 跨平台构建需在目标平台进行（Wails 不支持交叉编译到 Windows/macOS），需配置 CI；
- WKWebView 调试需 Safari 开发者工具，生态与资料少于 Chromium；
- 托盘、单实例、系统通知、自动更新等能力需自行选库补齐（见 3.4）。

### 3.2 总体选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 桌面框架 | Wails v2 | 轻量、Go 后端、系统 WebView |
| 后端语言 | Go 1.27+ | 子进程管理直接、标准库强、单二进制产出 |
| 前端框架 | Vue 3 + `<script setup>` + TypeScript | 与现有项目技术栈一致 |
| 前端构建 | Vite（Wails 模板内置） | HMR、构建快 |
| 状态管理 | Pinia | 轻量、类型友好 |
| UI 组件 | Naive UI（备选 Element Plus） | 组件完整、暗色主题好、纯 CSS 无字体依赖 |
| 样式 | UnoCSS | 原子化，开发效率高 |
| 通信 | Wails 绑定方法 + Events | 无需手写 IPC 协议，自动生成 TS 绑定 |
| 持久化 | JSON 文件（`os.UserConfigDir`） | 配置量小；安装历史量大时可切 bbolt |
| 测试 | `go test` + Vitest | 后端解析逻辑为主，前端组件少量 |
| 打包 | `wails build` + ad-hoc 签名脚本（公证待有账号后启用） | 见 11 章 |

### 3.3 后端 Go 依赖清单

| 用途 | 库 | 备注 |
| --- | --- | --- |
| 单实例 | `github.com/gofrs/flock` | 防止多开争抢 adb server |
| 系统通知 | `github.com/gen2brain/beeep` | macOS/Windows 可用；失败不影响主流程 |
| 安装历史存储 | `go.etcd.io/bbolt`（P1 再引入） | 首版用 JSON |
| 系统托盘（P2） | 视 Wails 版本能力，或 `fyne.io/systray` | 需与 Wails 事件循环协作，优先级低 |

### 3.4 平台差异与能力补齐

| 能力 | macOS | Windows | 实现方式 |
| --- | --- | --- | --- |
| 窗口 | WKWebView | WebView2（系统组件） | Wails 原生 |
| 文件对话框 | `runtime.OpenFileDialog` | 同左 | Wails 原生 |
| 文件拖拽 | WKWebView 支持 HTML5 DnD；Wails 较新版本提供 `OnFileDrop` | 同左 | 优先用 Wails API，回退 DOM drop 事件 |
| 单实例 | flock 锁 + 唤醒已有窗口 | 同左 | 自研 |
| 托盘 | 需 Wails 版本支持或第三方 | 同左 | P2 |
| 系统通知 | `beeep`（基于 osascript/UNUserNotification） | `beeep` | 可选 |
| 本地网络权限 | `Info.plist` 声明 + 系统授权 | 无需 | 见 11.2 |
| 自动更新 | 自研（下载 dmg 引导替换） | 自研（下载安装包） | P2 |

> 托盘与拖拽的 API 稳定性需在 M0 阶段用最小样例验证，避免 M3 才暴露阻塞。

### 3.5 adb server 策略

- 默认使用**独立端口**（如 `5038`），与用户机器上可能存在的 `5037`（Android Studio）隔离，避免"server 被 kill""版本不匹配"等干扰；
- 所有命令统一前缀 `-P <port>`；
- 启动时 `adb -P <port> start-server`，退出时**不**主动 `kill-server`（保留缓存可加速下次启动），在设置中提供"清理 adb server"入口；
- 若用户选择"复用系统 adb"，则探测 `adb version` 与路径，要求 ≥ 30.0.0（配对能力所需）。

## 4. 系统架构

### 4.1 进程模型

```text
┌─────────────────────────────────────────────────────────────┐
│ WireDeck 进程（Wails 单二进制）                                │
│                                                             │
│  ┌──────────────────────── Go 后端 ────────────────────────┐  │
│  │  ┌──────────────┐  ┌──────────────┐  ┌───────────────┐  │  │
│  │  │ AdbRunner    │  │ DeviceService│  │ InstallService│  │  │
│  │  │ exec/超时/流 │  │ 发现/配对/连接│  │ 队列/进度/校验 │  │  │
│  │  └──────┬───────┘  └──────┬───────┘  └───────┬───────┘  │  │
│  │         └────────┬────────┴──────────┬───────┘          │  │
│  │                  ▼                   ▼                  │  │
│  │           ┌─────────────┐     ┌─────────────┐           │  │
│  │           │ AppService  │     │ LogService  │           │  │
│  │           └─────────────┘     └─────────────┘           │  │
│  │                                                         │  │
│  │  spawn: adb -P 5038 ... → adb server :5038 → 设备 (Wi-Fi)│  │
│  └──────────────────────────┬──────────────────────────────┘  │
│                             │ 绑定方法调用 / EventsEmit        │
│  ┌──────────────────────────▼──────────────────────────────┐  │
│  │ 系统 WebView（WKWebView / WebView2）                     │  │
│  │  Vue 3 + Pinia + Router：设备 / 安装台 / 应用 / 日志 / 设置│  │
│  └─────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

与 Electron 的关键差异：**没有 preload 层与手写 IPC**。Wails 在构建时扫描 `App` 结构体的导出方法，生成 `frontend/wailsjs/go/main/App.{js,d.ts}`，前端以 Promise 形式直接调用；后端通过 `runtime.EventsEmit` 推送事件。

### 4.2 后端模块职责

| 模块 | 职责 | 关键设计 |
| --- | --- | --- |
| `AdbRunner` | 统一封装 adb 子进程调用 | 参数数组化（禁止字符串拼接/`sh -c`）；`exec.CommandContext` 实现超时与取消；stdout/stderr 分流；原始命令与输出留痕 |
| `AdbServerManager` | adb 二进制解析、端口选择、server 启停 | 查找优先级：用户指定 → 应用内置 → 系统 PATH；`adb version` 探测 |
| `DeviceService` | 发现、配对、连接、状态机 | 状态：`discovered → pairing → paired → connected → offline`；并发安全（mutex） |
| `ApkInspector` | 安装前静态解析 APK | 优先调用 `aapt2 dump badging`；缺失时降级解析 binary XML |
| `InstallService` | 安装任务队列 | 同设备串行、跨设备并行；阶段进度；可取消；结果与错误码 |
| `AppService` | 应用列表、详情、卸载、导出 | 缓存 + 手动刷新；`dumpsys` 解析 |
| `FileService` | push / pull / 截图 / 录屏 | 流式传输，进度回调 |

### 4.5 数据流约定

- 前端通过自动生成的绑定调用后端方法，**不直接访问文件系统或进程**；
- 长任务（安装、logcat、文件传输）采用 **方法启动 + 事件推送进度** 的组合，事件统一携带 `taskId`；
- 所有事件由后端单点发出（`App.emit`），避免多处拼写不一致；
- 每个 adb 调用记录结构化日志：`{ ts, level, cmd, device, durationMs, exitCode }`；
- 并发控制：设备状态、任务队列、logcat 流均以 Go 的 `sync.Mutex` / channel 保护，禁止在事件回调中做阻塞 I/O。

## 5. 核心流程设计

### 5.1 无线配对流程（Android 11+）

```text
用户                          前端(Vue)                      后端(Go)                   手机
 │ 打开"无线调试"                │                             │                       │
 │─────────────────────────────▶│ 点击"自动发现"                │                       │
 │                              │────────────────────────────▶│ adb mdns services      │
 │                              │                             │──────────────────────▶│
 │                              │                             │◀── _adb-tls-pairing    │
 │                              │ 展示设备 + 提示输入配对码       │                       │
 │ 输入 6 位配对码                │                             │                       │
 │─────────────────────────────▶│ Pair({host, pairPort, code}) │                       │
 │                              │────────────────────────────▶│ adb pair host:port code│
 │                              │                             │──────────────────────▶│
 │                              │                             │◀── Successfully paired │
 │                              │                             │ adb connect host:connPort
 │                              │                             │──────────────────────▶│
 │                              │                             │◀── connected to ...    │
 │                              │◀── 事件 device:changed       │                       │
```

**实现要点**

1. `adb mdns services` 输出形如 `adb-XXXXXX._adb-tls-pairing._tcp. 192.168.1.23:37123`，需同时解析服务名、IP、端口；配对服务与连接服务是两条不同记录。
2. 配对与连接是**两步**：`pair` 成功后必须再 `connect` 到无线调试页面显示的"IP:端口"（通常是另一个端口），否则状态停在 paired。
3. `adb pair host:port code` 支持一次性传码（adb ≥ 30.0.0）；失败时回退交互式，需处理 stdin 与 ANSI 提示。
4. 配对码错误返回 `Failed to pair: wrong password`，需提示"配对码失效，请重新生成"（配对码会轮换）。
5. 连接成功后用 `getprop ro.product.model` 补全设备名，serial 形如 `192.168.1.23:37123`。
6. Go 侧 `exec.CommandContext` 设置 10s 超时，配对失败不重试（配对码一次性），连接失败可重试 3 次（指数退避）。

### 5.2 有线通道（USB 直连）与低版本转无线

#### 5.2.1 USB 直连

USB 是 adb 的原生通道。插入数据线后 `adb devices` 会直接列出设备，`install`、`push`、`logcat` 全部可用，**不需要配对码，也不依赖 Wi-Fi**。适合大批量装机、首次配置，以及无线不可达时的兜底。

```text
插入数据线
  → adb devices 发现设备，状态 unauthorized
  → 手机弹出"允许 USB 调试吗？"→ 用户点"允许"（可勾选"一律允许"）
  → 状态变为 device → 可安装 / 推送 / 抓日志
  → 可选：点击"转为无线"执行 adb tcpip 5555（低版本设备）
```

**厂商限制（关键）**

`USB 调试` 与 `USB 安装` 是**两个独立开关**。只开前者时，连接正常但装包会返回 `INSTALL_FAILED_USER_RESTRICTED`：

| 厂商 / 系统 | 需额外开启的开关 | 位置 |
| --- | --- | --- |
| 小米 / Redmi（MIUI、HyperOS） | "USB 安装"；部分版本还需登录小米账号开启"USB 调试（安全设置）" | 设置 → 更多设置 → 开发者选项 |
| OPPO / 一加 / realme（ColorOS） | "USB 安装" | 设置 → 系统设置 → 开发者选项 |
| vivo / iQOO（OriginOS） | "USB 调试（安全设置）" | 设置 → 系统管理 → 开发者选项 |
| 华为（EMUI / HarmonyOS 非 NEXT） | "仅充电模式下允许 ADB 调试"、"USB 安装" | 设置 → 系统和更新 → 开发人员选项 |
| 三星 / Pixel / 原生 Android | 仅需"USB 调试" | 开发者选项 |

WireDeck 的处理：

- 错误码为 `INSTALL_FAILED_USER_RESTRICTED` 时，按设备品牌直接给出上述路径，而不是只显示原始错误；
- 设备卡片提供"USB 安装自检"入口：检测设备授权状态与品牌，提示还缺哪一项；
- 文档与下载页提供"各品牌开启 USB 安装"的图文说明。

**传输方式并存策略**

- 设备列表按 `USB` / `Wi-Fi` 分组展示；
- 同一台手机两种连接并存时，默认走 USB（更稳定、更快）；
- 无线断开但 USB 在线时自动切换并提示；
- 安装与传输逻辑与通道无关，统一由 `AdbRunner` 按 serial 路由。

#### 5.2.2 低版本设备（Android 5–10）：USB 转无线

```text
USB 连接 → adb devices 确认 → 用户点击"转为无线" →
adb -s <usbSerial> tcpip 5555 → 提示可拔线 → adb connect <ip>:5555
```

- IP 获取：`adb shell ip route` 或 `ip -f inet addr show wlan0`，正则提取；
- `tcpip` 后设备重启 adbd，需等待 1–2 秒再连接，失败重试 3 次；
- 该模式下设备重启后无线调试失效，需重新 USB 引导，UI 需提示。

### 5.3 APK 安装流程

```text
拖入 APK
  → ApkInspector 解析（包名/版本/minSdk/ABI/签名/是否 split 组）
  → 展示确认面板（目标设备、包名、版本、参数）
  → 进入队列（同设备串行）
  → adb -s <serial> install [flags] <apk>
      ├─ 输出 "Performing Streamed Install"
      ├─ 成功： "Success"
      └─ 失败： "Failure [INSTALL_FAILED_XXX: message]"
  → 回读 dumpsys package <pkg> 校验 versionCode（P1）
  → 写安装历史 + 通知
```

**命令构造（Go）**

```go
args := []string{"-P", port, "-s", serial, "install"}
if opt.Replace        { args = append(args, "-r") }
if opt.AllowDowngrade { args = append(args, "-d") }
if opt.GrantPermissions { args = append(args, "-g") }
if opt.AllowTest      { args = append(args, "-t") }
if opt.UserID != nil  { args = append(args, "--user", strconv.Itoa(*opt.UserID)) }
args = append(args, apkPath)

// 多 split
args = []string{"-P", port, "-s", serial, "install-multiple", "-r"}
args = append(args, splitPaths...)
```

**进度模型**（诚实设计）

`adb install` 自身不暴露字节进度，因此分层：

| 阶段 | 是否可量化 | 实现 |
| --- | --- | --- |
| 解析 APK | ✅ 字节 | 读取文件头与 manifest，按文件大小计算 |
| 传输 | ⚠️ 不可精确 | "传输中"脉冲动画 + 耗时；或改用 `push + pm install` 换取百分比 |
| 安装执行 | ❌ | "安装中"，解析 stdout 行切换状态 |
| 校验 | ✅ | 单次读取，显示"校验中" |

> 备选（P1）：`adb push <apk> /data/local/tmp/<hash>.apk` 可获得按百分比的传输进度，再 `pm install -r`，最后清理。代价是设备端临时占用空间与部分 ROM 的限制。默认仍用 `adb install`，设置中提供"精确进度模式"开关。

**参数默认值**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-r` 覆盖 | 开 | 日常升级必需 |
| `-d` 降级 | 关 | 降级有数据不兼容风险 |
| `-g` 授权 | 关 | 仅调试场景需要 |
| `-t` 测试包 | 关 | 调试包才需要 |
| `--user` | 不传 | 由系统默认用户决定 |

### 5.4 应用列表与详情

```text
adb -s <serial> shell pm list packages -3      # 第三方
adb -s <serial> shell pm list packages -s      # 系统
adb -s <serial> shell dumpsys package <pkg>    # 版本、安装时间、权限
```

- 列表为纯文本，逐行 `package:com.xxx`；
- **性能优化**：设备应用多时逐包 `dumpsys` 会非常慢（每包 100–300ms）。策略：列表先出，版本信息按可见行懒加载（虚拟滚动触发），缓存本次会话结果；
- 图标：P1 采用"首字母色块占位"；P2 再考虑 `aapt2 dump badging` 或设备端截图方案。

### 5.5 文件传输

- push：`adb -s <serial> push <local> <remote>`，解析 `1.2 MB/s (xxx bytes in y.yyys)` 计算进度；
- pull 同理；
- 截图：`adb -s <serial> exec-out screencap -p`，二进制经 stdout 返回，**必须**用 `io.ReadAll`/Buffer 处理而非字符串（避免 `0x0A` 被转换）；保存到用户图片目录并生成缩略图；
- 大文件统一走流式（`io.Copy`），禁止一次性读入内存。

### 5.6 日志（logcat）

- 启动：`adb -s <serial> logcat -v threadtime`，`bufio.Scanner` 按行读取（**必须**调大 `Scanner.Buffer`，默认 64KB 行限制会截断长日志）；
- 后端环形缓冲 + 前端虚拟列表，避免 DOM 爆炸；
- 过滤在前端做（级别、TAG、关键字），暂停时不停止后端读取（防止缓冲区阻塞），恢复时补齐；
- 导出：按当前过滤条件落盘为 `.log`；
- 设备断线时自动重连并标记"已重连 N 次"。

### 5.7 屏幕镜像（P2）

两条路线，评审时二选一：

| 路线 | 方案 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 集成 scrcpy | 随包下载 scrcpy + scrcpy-server，独立窗口 | 低延迟（30–60fps）、支持触控回传 | 二进制体积大；与 Wails 窗口集成复杂 |
| B. 截图轮询 | `screencap` 循环（1–5fps） | 纯 Go 实现、简单、无额外依赖 | 帧率低、无触控；每次 100–300ms |

建议：B 作为"快速预览"，A 作为正式镜像方案，单独评估。

### 6.5 安全边界

- 前端无文件系统与进程访问能力，一切经绑定方法；

- 后端对路径参数做绝对路径校验与存在性检查，避免误操作系统文件；
- 设备敏感信息（配对码）只存在于内存与单次调用参数中，不写入日志。

| 卸载 | `adb -s <s> uninstall [-k] --user 0 <pkg>` | `Success` / `Failure [DELETE_FAILED_...]` |
| 应用列表 | `adb -s <s> shell pm list packages [-3|-s]` | 每行 `package:<name>` |
| 应用详情 | `adb -s <s> shell dumpsys package <pkg>` | `versionCode=`、`versionName=`、`firstInstallTime`、`granted=true` |
| APK 路径 | `adb -s <s> shell pm path <pkg>` | `package:<path>` |
| 启动应用 | `adb -s <s> shell am start -n <pkg>/<activity>` | `Error type 3` 表示组件不存在 |
| 强停 | `adb -s <s> shell am force-stop <pkg>` | 退出码 |
| 清数据 | `adb -s <s> shell pm clear <pkg>` | `Success` |
| 推送 | `adb -s <s> push <local> <remote>` | `... bytes in ... s` |
| 拉取 | `adb -s <s> pull <remote> <local>` | 同上 |
| 截图 | `adb -s <s> exec-out screencap -p` | 二进制 PNG，校验魔数 `89 50 4E 47` |
| 录屏 | `adb -s <s> shell screenrecord --time-limit 180 <remote>` | 结束需 `pull` |
| 日志 | `adb -s <s> logcat -v threadtime` | 行格式 `MM-DD HH:mm:ss.mmm PID TID L TAG: msg` |
| 设备属性 | `adb -s <s> shell getprop <key>` | 单行文本 |
| 屏幕 | `adb -s <s> shell wm size` / `wm density` | `Physical size: WxH` |
| 电池 | `adb -s <s> shell dumpsys battery` | `level:`、`status:` |
| 重启 | `adb -s <s> reboot [recovery|bootloader]` | 设备会立即离线 |

**输出解析注意**

- 所有命令统一 `LANG=C`、`LC_ALL=C` 环境变量，避免本地化输出差异；
- 换行使用 `\n`，但 `\r` 可能出现在进度输出中，需按行切分并去重；
- `adb` 的部分错误输出到 stderr（如 `error: no devices/emulators found`），必须同时捕获两路；
- 退出码不可靠（部分失败仅体现在 stdout），**以文本判定为主、退出码为辅**；
- Windows 下 `adb.exe` 的路径与参数转义需单独测试（Go 的 `exec.Command` 不经 shell，天然规避大部分问题）。

## 9. UI / UX 设计

### 9.1 信息架构

```text
WireDeck
├── 侧边栏
│   ├── 设备（连接状态、当前选中设备）
│   ├── 安装台（拖拽区、队列、历史）
│   ├── 应用管理
│   ├── 文件与截图
│   ├── 日志
│   └── 设置
└── 顶部栏：当前设备切换器 + 连接状态 + 全局操作
```

### 9.2 页面要点

**设备页**

- 空状态：引导卡片（三步：打开开发者选项 → 开启无线调试 → 输入配对码）；
- 发现列表：设备名 + IP + 状态徽标；
- 配对弹窗：IP、配对端口、连接端口、6 位配对码（数字键盘友好），错误就地提示；
- 已连接卡片：型号、系统版本、电量、存储、快捷操作（截图/装包/重连）。

**安装台**

- 全窗口拖拽区，拖入高亮；
- 队列列表：文件、包名、大小、目标设备、阶段、进度、耗时、结果；
- 批量模式：多设备分发开关；
- 失败详情抽屉：错误码、原始输出、建议、复制按钮。

**应用管理**

- 表格 + 搜索 + 作用域切换（第三方/系统/全部）；
- 行内操作：卸载、导出、启停；
- 危险操作统一二次确认（说明影响 + 可要求输入包名后 4 位）。

**日志页**

- 工具栏：级别下拉、TAG 输入、关键字、暂停/继续、清空、导出；
- 虚拟滚动；等宽字体；ERROR/WARN 行内高亮。

### 9.3 交互原则

1. **状态可见**：任何耗时操作都应有阶段与结果，不出现"点击后无反应"；
2. **失败可解释**：错误信息三段式 = 发生了什么 + 为什么 + 怎么做；
3. **危险可逆**：卸载、清数据、重启需确认；安装默认参数保守；
4. **多设备不混淆**：所有操作入口都显示目标设备名，切换设备时队列不串台。

### 9.4 WKWebView 兼容注意事项

- 避免依赖 Chromium 专属 CSS/JS 特性（如 `-webkit-app-region` 拖拽区、`showOpenFilePicker` 等非标准 API）；
- 拖拽文件优先使用 Wails 原生 `OnFileDrop`，DOM `drop` 事件作为回退；
- 字体渲染在 macOS 与 Windows 差异明显，字号与行高使用相对单位；
- 日期/数字格式化统一用 `Intl`，避免平台差异；
- 深色模式需要同时处理 `prefers-color-scheme` 与 Wails 的窗口外观设置。

## 11. 打包与分发

### 11.1 构建

```bash
# 开发（热重载）
wails dev

# macOS 通用二进制（arm64 + amd64）
wails build -platform darwin/universal -clean

# Windows（需在 Windows 环境执行）
wails build -platform windows/amd64 -clean
```

- `wails.json` 关键配置：`outputfilename`、`frontend:build`（`pnpm build`）、`frontend:dev:watcher`；
- Go 侧用 `//go:embed` 内置前端产物与图标；`platform-tools` 不入包，走首启下载（见 11.5）；
- 资源与窗口属性在 `main.go` 的 `wails.Run` 中配置（标题、尺寸、最小尺寸、背景色）。

### 11.2 macOS 签名与分发（无付费账号的可行路径）

**结论**：Developer ID 签名 + 公证需要 Apple Developer Program 账号（$99/年）。没有账号时，应用**仍然可以分发给他人**，代价是首次打开需要用户手动放行。首版采用路径 B；代码无需改动，未来有预算时切换到路径 A 即可。

#### 路径 A：Developer ID + 公证（长期推荐）

```text
1. 证书：Apple Developer Program → Developer ID Application
2. 构建：wails build -platform darwin/universal
3. 签名：先签可执行文件，再签 .app 本体（避免 --deep 的已知问题）
         codesign --force --options runtime --timestamp \
           --entitlements build/darwin/entitlements.plist \
           --sign "Developer ID Application: <Team>" WireDeck.app/Contents/MacOS/WireDeck
         codesign --force --options runtime --timestamp \
           --sign "Developer ID Application: <Team>" WireDeck.app
4. 打包：dmgbuild / create-dmg 生成 .dmg
5. 公证：xcrun notarytool submit WireDeck.dmg --apple-id ... --team-id ... --password ...
6. 装订：xcrun stapler staple WireDeck.dmg
7. 验证：spctl -a -vv -t install WireDeck.dmg
```

**entitlements 至少包含**

```xml
<key>com.apple.security.network.client</key><true/>
<key>com.apple.security.network.server</key><true/>
```

**Info.plist 必填**

```xml
<key>NSLocalNetworkUsageDescription</key>
<string>WireDeck 需要访问本地网络，以发现并连接同一 Wi-Fi 下的安卓设备。</string>
```

#### 路径 B：Ad-hoc 签名、不公证（首版采用，0 成本）

```bash
# 1. ad-hoc 签名（无需证书；Apple Silicon 上未签名二进制可能被内核拒绝，必须做）
codesign --force --options runtime -s - WireDeck.app
codesign -dv --verbose=4 WireDeck.app    # 验证

# 2. 打包 DMG
create-dmg WireDeck.dmg WireDeck.app

# 3. 生成校验清单（随发布页提供）
shasum -a 256 WireDeck.dmg
```

要点：

- ad-hoc 签名只解决"本机能否启动"，**不具备公证效果**；
- 用户从网络下载的包带 `com.apple.quarantine` 属性，首次打开会被 Gatekeeper 拦截；
- macOS 15 及以后（含 26）"右键 → 打开"不再直接放行，必须进入"系统设置 → 隐私与安全性 → 仍要打开"；macOS 14 及以下可以右键打开；
- 兜底命令 `xattr -dr com.apple.quarantine /Applications/WireDeck.app` 写进下载页，并说明其含义，避免用户误以为是常见做法。

#### 11.2.1 用户安装指引（随 DMG 附带 `安装说明.txt`，并在下载页展示）

```text
1. 双击打开 DMG，将 WireDeck 拖入"应用程序"。
2. 双击 WireDeck：
   - 若提示"无法验证开发者"：
     · macOS 15+：系统设置 → 隐私与安全性 → 页面底部"仍要打开" → 输入密码 → 再次打开；
     · macOS 14 及以下：Finder 中右键 WireDeck → "打开" → 确认。
3. 若仍无法打开，打开"终端"执行：
   xattr -dr com.apple.quarantine /Applications/WireDeck.app
   然后重新双击。
4. 首次启动会请求"本地网络"权限，请选择"允许"，否则无法发现设备。
```

#### 11.2.2 可选的分发增强

| 方式 | 说明 | 门槛 |
| --- | --- | --- |
| Homebrew Cask | `brew install --cask --no-quarantine wiredeck`（自建 tap） | 用户需会用 brew |
| 源码构建 | 提供一键脚本，用户自行编译 | 需 Go + Xcode CLT |
| Developer ID 公证 | 消除绝大部分拦截，见路径 A | $99/年 |

**不建议**：引导用户使用绕过 Gatekeeper 的第三方工具，或建议关闭系统安全策略（`spctl --master-disable`）。

### 11.3 Windows 签名（首发不做）

首发仅 macOS。Windows 版本排到 v0.2 之后再评估：

| 方案 | 说明 | 成本 |
| --- | --- | --- |
| OV 代码签名证书 | `signtool sign /fd sha256 /tr <timestamp> /td sha256` | 约 $200–400/年 |
| EV 证书 | 硬件令牌，SmartScreen 声誉起量快 | 更贵，周期长 |
| 暂不签名 | 用户需在 SmartScreen 中选"仍要运行" | $0，体验差 |

> 若后续发布 Windows 版，新二进制常被 Defender 误报，需预留申诉时间。

### 11.4 自动更新（P2，自研）

Wails 无内置 updater，方案：

1. 发布端维护 `latest.json`（版本、下载地址、SHA-256、更新说明）；
2. 客户端启动时（或每日一次）检查，版本比较用 `golang.org/x/mod/semver`；
3. 下载新包到临时目录并校验摘要；
4. macOS：提示用户运行新 `.dmg` 覆盖安装（不做自动替换，规避签名与运行中替换问题）；
5. Windows：可下载 NSIS 安装包并静默升级。

> 首版不做自动更新，仅提供"检查更新"按钮跳转下载页。

### 11.5 platform-tools 获取策略

| 方案 | 做法 | 评估 |
| --- | --- | --- |
| A. 随包分发 | 构建期下载并打入应用资源 | 开箱即用；受 Google SDK 条款约束；体积 +13MB |
| B. 首次运行下载 | 从官方地址下载 zip，校验 SHA-256，解压到 `UserConfigDir/WireDeck/bin` | 条款风险低；需网络；需处理失败 |
| C. 使用系统 adb | 探测 PATH 与常见安装路径 | 零下载；用户环境差异大 |

**建议组合**：默认 C → 否则 B（引导下载）→ 设置中允许手动指定；企业内网场景可提供 A 的离线构建开关。

### 11.6 发布渠道

- macOS：GitHub Releases（dmg）+ 官网下载页；
- Windows：GitHub Releases（exe/msi）；
- 版本号：语义化版本，`0.x` 快速迭代；
- 每个 release 附 SHA-256 清单与更新说明。

### 12.1 后端单元测试（`go test`）

- Vitest：store 逻辑、错误码文案渲染、队列状态机；

  - 方案 1：前端以纯 Vite 模式运行，用 `wailsjs` mock 层 + Playwright 做浏览器 E2E（覆盖 UI 交互）；
  - 方案 2：桌面端关键路径手工回归清单（见 12.5），每次发版执行。

### 12.4 真机矩阵

| 维度 | 覆盖 |
| --- | --- |

4. 应用列表加载 ≤ 2s（100 个应用）、卸载、导出；

6. 关闭窗口后无残留 adb 子进程、无僵尸进程；
7. ad-hoc 签名包在全新 macOS 用户环境下，按《安装说明》可成功放行并启动。

| 厂商 ROM 限制安装（MIUI/ColorOS 等） | 高 | 用户装不上 | 错误码给出精确开关路径；文档"常见问题"；引导 `-g` 与"USB 安装" |
| adb server 版本/端口冲突 | 中 | 连接异常 | 独立端口 + 版本探测 + 设置项切换 |
| mDNS 被系统或路由器阻断 | 中 | 发现失败 | 手动输入 IP 兜底；"诊断"按钮执行 `adb mdns check` |
| macOS 本地网络权限未授予 | 中 | 发现/连接失败 | Info.plist 声明；首次运行引导；失败时跳转系统设置 |
| Wails 生态较小、部分 API 不稳定 | 中 | 功能补齐受阻 | M0 阶段验证拖拽/托盘/单实例；不稳定的能力降级为前端实现 |
| WKWebView 渲染差异 | 中 | UI 与设计稿不一致 | 组件库保守选型；macOS 真机走查；避免 Chromium 专属 API |
| 后续 Windows 构建需 Windows 环境 | 低（首发不做） | 发布效率低 | GitHub Actions 矩阵构建，v0.2 再处理 |
| APK 解析（binary XML）实现复杂 | 中 | 校验能力缺失 | 优先 `aapt2`（platform-tools 同包提供），缺失时降级为 `dumpsys` 比对 |
| 安装进度不可精确 | 高 | 体验打折 | 阶段进度 + 可选"精确进度模式"（push + pm install） |
| 大文件内存占用 | 低 | 崩溃 | 全链路流式；限制单文件 2GB 并提示 |
| 与现有工具（Android Studio）抢设备 | 低 | 连接抖动 | 独立 5038 端口；退出不 kill server |
| 纯血鸿蒙不支持 adb | 中 | 无法支持 | 启动检测并提示"暂不支持" |
| 未公证分发导致用户无法打开 | 高 | 下载后打不开而流失 | DMG 内附放行指引 + 下载页图文 + 兜底命令；重要用户一对一指导 |
| 无付费开发者账号 | 已发生 | 无法公证 | 首版走 ad-hoc 签名；预留升级路径，代码不变 |
| Windows Defender 误报（后续版本） | 中 | 用户不敢安装 | 提交误报申诉；发布页说明；尽早签名 |

## 17. 官网与部署计划（MVP 后执行）

> 本节记录已确认的协作方式，避免执行阶段偏离。官网不阻塞应用开发。

### 17.1 已确认的决策

| 事项 | 决策 |
| --- | --- |
| 启动时机 | 应用 MVP（M2 安装闭环）完成后启动，不占用开发主线 |
| 建站方式 | **由项目方在宝塔面板创建站点与申请 SSL**；开发方只负责上传构建产物与核对配置，确保面板站点列表、操作日志、SSL 记录完整 |
| 上传方式 | `rsync`（建议 GNU 版）或 `scp`，仅同步 `dist/` 产物，不覆盖站点根目录其他文件 |
| 技术方案 | 静态站：Astro 或 Vite + Vue 3，无后端、无数据库 |
| 下载分发 | 安装包放 GitHub Releases，官网只做链接与版本说明 |

### 17.2 站点规划

| 项 | 规划 |
| --- | --- |
| 域名 | `woyuxiaji.cn`（主域或 `www`，以实际解析为准） |
| 站点目录 | `/www/wwwroot/<站点目录>`（由面板创建，开发方只写入静态文件） |
| 页面 | 首页（介绍/截图）、功能、下载、安装指引（含 Gatekeeper 放行）、FAQ、更新日志、隐私政策 |
| SEO | 静态 HTML + `sitemap.xml` + `robots.txt` + Open Graph 图 |
| 版本联动 | 下载区读取 `version.json`（版本号、文件名、SHA-256、说明），发版只改该文件 |

### 17.3 执行前需要的信息

| 项 | 状态 | 用途 |
| --- | --- | --- |
| 服务器公网 IP、SSH 端口、用户名 | 待提供 | 上传与核对 |
| SSH 认证方式 | 建议密钥（`~/.ssh/config` 别名） | 避免明文密码 |
| 宝塔面板地址与版本 | 待提供 | 建站、SSL、运行目录确认 |
| 域名解析状态 | 待确认 | 站点绑定与证书申请 |
| 服务器所在地 / ICP 备案 | 待确认 | 大陆服务器未备案会阻断 80/443 |
| 站点目录名 | 面板建站时确定 | 上传目标路径 |

### 17.4 部署流程（MVP 后）

```text
1. 项目方：宝塔面板 → 新建站点（纯静态）→ 绑定域名 → 申请 Let's Encrypt
2. 项目方：把站点根目录、面板地址、SSH 信息告知开发方
3. 开发方：本地 pnpm build → 产物 dist/
4. 开发方：rsync 上传到站点根目录
5. 开发方：核对面板中站点状态、运行目录、SSL 有效期；浏览器与移动端验收
6. 双方：确认下载链接可访问、安装包 SHA-256 与发布页一致
```

### 17.5 注意事项

- 站点必须**先在面板创建**，不要直接改 Nginx 配置挂新站点，否则面板里没有该站点，后续续签 SSL、迁移、备份都会出问题；
- 若服务器在中国大陆，`.cn` 域名通常要求 ICP 备案，备案未完成时 80/443 可能被阻断，需准备香港/海外节点或非标准端口；
- 下载页必须包含 Gatekeeper 首次放行说明，否则用户会误以为"应用打不开"。
